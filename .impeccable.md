## Design Context

### Users
Single power user (developer/tech lead) who uses this as a personal operations dashboard for monitoring scheduled AI and script jobs. All three usage modes: quick morning health check, passive monitoring throughout the day, and deep-dive log investigation when things fail. Used on a laptop, often alongside a code editor.

### Brand Personality
Dense, precise, utilitarian. A technical cockpit — every element earns its space. Information-dense but scannable. Confidence through clarity, not decoration.

### Aesthetic Direction
- **Vibe**: Bloomberg terminal meets well-designed CLI — power-user density with modern type and layout
- **Theme**: Support both light and dark via system preference (currently dark-only)
- **Anti-references**: No over-designed dashboards (gratuitous animations, gradients, visual noise). No hacker-terminal retro aesthetic (green-on-black). Substance over style always.
- **References**: Grafana's density, Vercel dashboard's clarity, Linear's restraint

### Design Principles
1. **Density over decoration** — Pack information tight. Whitespace is a tool for grouping, not a filler.
2. **Scannable at a glance** — Status, health, and failures must be visible in under 2 seconds.
3. **Progressive disclosure** — Overview first, details on demand. Don't front-load complexity.
4. **Quiet until it matters** — Failures and warnings should pop visually. Success should be calm/recessive.
5. **No AI slop** — No gratuitous cards, no glow effects, no decorative sparklines. Every visual element must convey information.
